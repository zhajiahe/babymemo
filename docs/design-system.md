## 0. 实施状态与真实来源

**当前已实现**：React + 原生 CSS；`src/styles.css` 中的卡片、导航、表单、暖珊瑚色、`--bm-*` 变量、全局 `:focus-visible`、`prefers-reduced-motion` 和移动端布局。

**本文件新增的是产品设计规范**。下方带「目标 / 待迁移」的规则**尚未自动改造所有旧界面**；不要在 PR 或发布说明中宣称“全站无障碍达标 / token 化完成”。新增 UI 按这些规范实施，旧界面在相关功能迭代时分批调整。

唯一现有样式入口：`src/styles.css`。现阶段**没有** Tailwind、shadcn、Radix、深色主题或组件包；不要引用 FlareMo 的 `apps/web/src/index.css`、`--flame-*`、`bg-brand-gradient` 等不存在的资源。

## 1. 设计原则

1. **内容先于装饰**：宝宝的成长数据、日期、里程碑和照片是主角；界面只提供易读的容器。
2. **温暖但克制**：暖珊瑚只用于主要动作、选中状态和少量表达情绪的区域。普通数据区以白、浅灰、深色文字为主；一屏不叠加多个大型渐变。
3. **随手记录，状态明确**：用户应清楚知道「保存中 / 已保存 / 上传中 / 失败可重试」，不要让网络失败看起来像登录失效或数据丢失。
4. **有边界的 AI**：AI 和微信是记录入口，不能抢占核心成长信息；未配置时给设置入口，不显示虚假的成功状态。
5. **隐私感来自真实保护**：可显示「仅家人可见」，但不采用未经验证的绝对性隐私或安全承诺。

## 2. 颜色：现状基准与演进约束

下列色值来自当前 `src/styles.css`。**部分颜色仍是硬编码，这是待整理的技术债，而不是已完成的语义色体系**。

| 用途 | 当前值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#f7f8fa` | 冷中性但足够安静 |
| 卡片表面 | `#ffffff` | 内容及输入容器 |
| 主文字 | `#263342`（`--bm-ink`） | 新内容首选深墨色 |
| 次要文字 | `#526174`（`--bm-muted`） | 白色与浅灰背景下保持充足对比度 |
| 描边 | `#e3e8ee`（`--bm-outline`） | 卡片发丝线、次按钮 |
| 焦点强调 | `#a94b39`（`--bm-focus`） | 键盘焦点与交互提示 |
| 当前主按钮 | `#a94b39`（`--bm-brand`） | 白字对比度约 5.6:1，阶段一已实现 |
| 当前主按钮 hover | `#923f30`（`--bm-brand-hover`） | 更明确的悬停反馈 |
| 激活导航文字 | `#a94b39` | 暖珊瑚深色，优于高饱和大色块 |
| 激活导航底色 | `#fff0ea` | 轻量选中态 |

**新增视觉元素的做法**：

- 优先重用 `--bm-ink`、`--bm-muted`、`--bm-outline`、`--bm-focus` 及已有组件 class。新色值若多处出现，先在 `:root` 明确语义并统一使用，**不要引入第二套零散常量**。
- 主色专用于提交、保存、上传和当前导航等关键位置；统计卡的薄荷绿/淡紫色只用于区分内容，不承担主操作。
- **不要假设珊瑚色按钮上放白字就可读**。新按钮、提示和标签需实测对比度：普通正文与背景 ≥ 4.5:1；大字及关键图形 ≥ 3:1。未实测时应调整深色背景或改为深色文字。
- 错误、成功与警告**不能只靠颜色**：配合明确文字和必要图标。不要用品牌珊瑚冒充系统错误。
- 渐变预算：一屏最多一个主要情绪化区域（如当前 `.welcome`）；普通记录表单和数据面板保持纯色。

## 3. 字体、数字与排版

当前字体栈从 `Inter`、`SF Pro Display` 到系统字体、`PingFang SC` 和 `Microsoft YaHei`，定义于 `src/styles.css` 的 `:root`。不为一个 UI 改动引入网络字体依赖；字体载入失败时也必须能正常显示中文。

| 类型 | 新增界面建议 | 场景 |
| --- | --- | --- |
| 页面主标题 | 24–30px，字重 650–720 | 「成长记录」「家庭相册」 |
| 区块标题 | 16–18px，字重 600–700 | 卡片标题、模块标题 |
| 正文、表单输入 | 14–16px，行高 1.5–1.7 | 内容、输入、提示 |
| 辅助说明、导航 | 12–13px（**下限 12px**） | 时间戳、文件状态、分组 |
| 统计数字 | 24–28px，数字等宽 | 成长次数、身高体重 |
| 极小装饰符号 | 可以小于 12px，但不得承载必要中文信息 | 非语义标识 |

**阶段一已把样式表中的 10/11px 字号声明提升到 12px**，同时加入回归测试；新增文字继续保持 ≥12px，并在 iPhone 实机/模拟视口确认阅读性。

中文标题不使用夸张的负字距；阶段一已将 `h1`、`h2` 通用字距恢复为 `normal`，其他装饰性字距仍需在后续排版检查中评估。日期、时间、身高、体重等数字建议使用 `font-variant-numeric: tabular-nums`，单位与数值之间保持稳定间距。

## 4. 间距、圆角、阴影与边框

沿用当前的视觉尺度，**不要假装已经有完整 spacing tokens**：

- 基础间距建议按 4px 递增：4 / 8 / 12 / 16 / 24 / 32；相同层级的卡片与表单使用相同节奏。
- 输入/按钮：8–10px 圆角；普通卡片：12–16px；强调欢迎区：约 18–20px。保持同层级一致，不要求全部卡片统一成大圆角。
- 卡片边框使用 1px 浅色发丝线，阴影极轻（现有 `.card` 的低透明阴影）；不要靠重阴影把平铺页面做成浮层堆栈。
- 移动端优先减少横向拥挤，而不是一味缩小文字；内容和表单宽度必须适配 320px。
- 层级遵循：页面背景 → 内容卡片 → 交互弹出层/悬浮通知。图标不额外套五彩背景，除非确实用于一组统计维度。

## 5. 组件使用规则（与真实代码对应）

| 元素 | 现有入口 | 新增行为约定 |
| --- | --- | --- |
| 卡片 | `Card` / `.card` | 核心数据区域；不能为装饰连续嵌套多层 |
| 主按钮 | `Primary` / `.primary` | 当前表单或面板的主要动作通常只有一个 |
| 次按钮 | `.secondary` / `.light-btn` | 返回、重试、取消、非主操作 |
| 字段 | `Field` / `.field` | 始终有可读标签、必填提示、错误说明 |
| 导航 | `Nav` / `.sidebar` / `.mobile-nav` | 左侧桌面导航、底部手机导航；选中态一致 |
| 提示 | `Notice` / `.notice` | 操作成功/失败后反馈，必要时可以手动关闭 |
| 翻页 | `Pager` / `.pager` | 保留分页语义，不一次加载所有媒体 |
| 成长趋势 | `GrowthChart` / `.growth-chart` | 单位与日期明确，不凭视觉图形捏造结论 |
| 相册上传 | `Album` / `.upload-card` | 展示上传/重试/完成与失败清理状态 |
| AI 聊天 | `Assistant` / `.chat` | 根据当前 `babyId`，不能串档案 |
| 首次设置 | `Gate` / `.setup-guide` | 缺 Secrets 或 API 故障给出真实修复路径 |

当前组件多数仍在 `src/App.tsx` 内，而非独立 UI 目录。新增较大组件可逐步抽取，前提是仍复用同一套视觉和状态规则。

**交互红线**：破坏性动作二次确认；保存/上传期间避免重复提交；失败时保留输入；网络断连要提供重试入口；不可用的功能不要做成可点击按钮。录入宝宝生日、体格数据时明确日期和单位。

## 6. 移动端与媒体

现有响应式断点在 `src/styles.css` 中包含约 1050px、800px、480px；其中 ≤800px 使用底部 `.mobile-nav`。**新增断点前先检查现有布局**。

- 必测宽度：320、375、390、768、1280px，包含横竖屏、浏览器缩放和 iOS Safari 底部安全区。
- 新增触控目标以 **44 × 44 CSS px** 为目标，不要仅用 10px 文本构成可点击区域；包含图标按钮、删除、分页、底部导航。
- 表单在手机端保持清晰标签；软键盘弹出时操作按钮仍可达。不要用 `overflow:hidden` 意外截断文件列表或长错误信息。
- 多媒体卡片要保留长文件名换行/截断、懒加载和原始宽高比例的考虑；图片与视频不要在主屏自动全量下载。
- 上传说明不得宣称「支持所有 iPhone 视频」：HEIC/MOV 可以上传，但 **HEVC 解码、MOV 转码、视频封面和断点续传并未完整实现**。
- 进度指示应来自实际上传分片，不要模拟进度；取消或失败后能清理未完成上传的服务器资源。

## 7. 动效与反馈

现有导航和输入的过渡约 150–160ms，并已有 `@media (prefers-reduced-motion: reduce)` 全局兜底。

- 默认仅对 `opacity`、`transform`、颜色/边框等轻量属性过渡；交互反馈建议 ≤160ms，入场 ≤300ms。
- 禁止无目的的呼吸灯、背景粒子、连续自动切换的情绪文案、大片视差。记录列表一般**不需要**逐条入场动画。
- 重要状态变化要同步呈现文字：`正在上传…`、`已保存`、`上传失败，请重试`；动态提示不要闪退到来不及阅读。
- 降低动态效果的系统偏好必须生效。不得以动画代替用户能明确读取的状态。

## 8. 文案与隐私表达

- 产品中文术语固定：「宝宝」「家庭空间」「成长记录」「成长瞬间」「家庭相册」「AI 助手」「微信 ClawBot」。
- 中文使用全角标点、自然语气和省略号「…」；英文小标题采用 sentence case，非拉丁语言避免为了装饰强行扩展字距。
- 空状态包含下一步：如「还没有成长记录，添加第一条吧」，而不是只写「暂无数据」。
- 错误说明必须指出可采取的动作，不能只展示 `HTTP_500` 或默默清空表单。
- AI 的育儿建议不得包装为疾病诊断；成长数据的来源、日期、单位必须真实。
- 不要用「绝对安全」「零延迟」「上传永不失败」等未经验证的宣传语，尤其是涉及宝宝照片和敏感信息时。
