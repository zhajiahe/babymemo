## 实际运行的自动化场景

`scripts/e2e-local.mjs` 在临时 D1/R2 数据目录中调用完整 Wrangler 本地 Worker：

1. 健康检查、第一次初始化状态和两项 Secret 准备状态
2. 未登录拒绝、跨域 Origin 拦截
3. 无初始化密钥安装与第二次初始化拒绝
4. 退出、错误密码、正确密码登录、会话保护
5. 成长记录创建、分页查询、删除
6. 里程碑创建、查询、删除
7. OpenRouter 配置服务端加密存储，确保响应不回显 Key（未调用外部模型）
8. 私有 multipart 图片上传、分片校验、待上传状态
9. 原图访问控制、Range 响应、下载响应头
10. 缩略图回退、派生 JPEG 上传、媒体元数据修改
11. 媒体删除后读取返回 404
12. 取消未完成上传
13. 大于 8MiB 文件的真实两分片上传、读取已完成分片状态、继续第二分片、合并后 Range 完整性校验（本次新增）

Chromium 自动化覆盖：

- 桌面 React 页面登录
- 相册图片从表单上传、预览弹窗显示
- 编辑名称和拍摄日期，关闭弹窗后列表内容同步、删除媒体
- 390px 手机视口的底部导航、成长页与相册页加载、横向滚动溢出检查

## 按优先级排列的待解决问题

### P1 — 远端上传合并与 D1 提交的失败一致性

来源：`src/worker.ts` 的 `POST /api/upload/:id/finish`。当前先执行 `R2.multipart.complete()`，后执行 `D1.DB.batch(INSERT media, DELETE media_uploads)`。若 R2 合并成功但后续 D1 暂时失败，接口返回 `UPLOAD_FINISH_FAILED`；再次调用 R2 `complete()` 可能由于上传会话已结束而无法重复完成。产生「对象在 R2 但未收录 D1」的概率虽低，后果可能是无法恢复、重复上传和孤儿对象。**这是代码路径的故障注入风险，尚未在真实 Cloudflare 故障环境复现。**

建议：为上传记录引入明确 `completing/completed` 状态与幂等 finalization / reconciliation，补充在 D1 提交失败情况下的故障注入测试。不要仅通过自动 abort 处理已合并的 R2 对象。

### P1（新环境安全）— 没有初始化密钥后的抢注窗口

来源：`POST /api/bootstrap` 对所有访客开放（用户明确选择取消初始化密钥）。依靠 `owner(id=1)` 防止第二次初始化，但**不防止全新实例被第一个陌生访客抢先注册**。

建议：部署完成后立即初始化，或先用 Cloudflare Access/受限域名保护首次安装入口；不要为了避免抢注而偷偷重置现有 D1。

### P2 — 旧照片大文件回退和高流量

`GET /api/media/:id/thumbnail` 在不存在派生图时把**整张原图**回传给列表。旧媒体不具备缩略图时一屏多图可能消耗大量移动流量；`private, no-store` 缓存策略也意味着多次访问会重复请求。

建议：在受保护的独立任务中按批为既有原图补缩略图，保持私有访问；记录列表带宽与首次渲染耗时，验证 4G/弱 Wi-Fi。

### P2 — 长期未完成的上传与指纹匹配

`/api/upload/pending` 只返回最近 30 个会话，当前没有到期/清理任务；过期的 R2 multipart 可能累积，较老会话不便从 UI 取消。续传只对首尾 64KiB 的采样摘要与文件元数据做一致性比较，**并不验证中间内容**，极少数同首尾同大小但中间发生变化的文件可能错误复用已上传分片。

建议：为过期会话增加受保护的垃圾回收和后台日志；对强完整性场景采用完整文件哈希或在完成前做可验证的分块摘要。保留用户显式取消能力。

## 2026-10-12 后续修复：上传最终提交幂等性（PR #11）

针对上述 P1 风险，新增 `src/upload-finalize.mjs`：首先检查 R2 对象是否已经存在并匹配预计字节数，避免对已完成的 multipart 再次调用 `complete()`；R2 完成后 D1 失败会保留未完成会话，下次调用直接补记元数据；若 D1 事务成功但 HTTP 响应丢失，再次调用返回 200；并发请求在 D1 已写入相同 media ID 后也返回成功。支持在相册「待续传文件」里不重选文件，直接点击「完成保存」。取消上传会拒绝删除已在 R2 合并但还未登记 D1 的对象。

通过 **纯 Node 故障注入测试**模拟「D1 第一次失败、R2 已完成」「R2 响应丢失但对象存在」「D1 并发唯一索引冲突」「R2 预存对象大小不一致」，及**真实隔离 Worker HTTP E2E**重复调用 `finish`，验证幂等性。这些验证不是生产 Cloudflare 的故障注入，不包括进程在任意位置被杀、长时间 Cloudflare/D1 宕机、线上跨区域一致性异常。
