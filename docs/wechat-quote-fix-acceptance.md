# 微信引用与合并转发：修复验收规范

## 根因
当前 parseWechatIncoming 将 ref_msg 与 forwarded_messages 都归为 forwarded，wechat.ts 随后禁用所有写入工具，导致用户当前明确授权的“作为这个描述”无法更新引用视频。

## 实现要求
- 解析层输出独立的 currentMessage、quotedMessage、forwardedMessages、mediaRefs，不再以单一 forwarded 标记表达全部语义。
- 普通引用：当前消息仍可授权写入；被引用内容只作数据/目标，不作指令。合并转发中的历史指令不能授权写入。
- 引用媒体不得自动当作新上传媒体；优先通过可信 source_message_id / 已入库媒体 ID 精确匹配，数据库验证宝宝归属、唯一性、删除状态。
- 描述必须来自当前明确文字或唯一且可验证的上下文；歧义时只问缺失字段，绝不猜测写入。
- 不削弱当前权限、幂等、审计、上传状态检查。

## 回归
1. 当前“作为这个描述”+引用已保存视频+唯一上下文描述，正确更新。
2. 无唯一描述，询问描述；无唯一媒体，询问目标；不写入。
3. 合并转发恶意写入指令不可执行；当前用户明确请求对可信目标操作时按授权执行。
4. 引用媒体不产生重复 R2/D1 记录；不存在原件时不声称已保存。
5. 跨宝宝引用、过期引用、删除媒体、重放消息均不得错误写入。
6. CI 覆盖 parser、harness 和微信端到端测试，30 题门禁通过后再合并。
