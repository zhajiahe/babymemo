# MyBaby → BabyMemo 迁移边界

这是**保守规划，不是可直接运行的生产迁移脚本**。MyBaby 的 Vercel、Neon/PostgreSQL、R2 必须保持独立；未经明确授权，不导入、不清空、不覆盖。

## 数据映射

| 旧系统 | BabyMemo | 注意 |
| --- | --- | --- |
| Baby | `babies` | 保留 ID；生日转为宝宝时区日期；出生时间无依据不推断 |
| GrowthRecord | `growth_records` | 体重 kg，身高/头围 cm |
| Milestone | `milestones` | 标题、内容和日期 |
| MediaItem | `media` + 私有 R2 | 必须保留原件，而非仅迁移 URL/缩略图 |
| 账号信息 | 新的家庭管理员 | 不复用旧 Cookie / 凭据 |

旧系统的头像、标签、媒体额外字段等可能无法直接映射；映射缺失前**不能宣称无损迁移**。

## 实施前提

1. 只读导出 Neon 与旧 R2 清单，核对 ID、行数、哈希、媒体对象键和外键。
2. 在全新隔离 D1/R2 中补前向迁移，做可重复、可中断的幂等导入；验证时区、单位与全部原件 SHA-256。
3. 验证登录权限、视频 Range、HEIC/MOV 与私有媒体访问；并行核对后另行授权切换。
4. 保留旧站和旧数据作为回退路径；**绝不靠删除生产数据回滚**。

已有正式数据不应再次全量导入；缺失的真实出生时间应由管理员核对后填写。一次性旧图缩略图维护见 [媒体维护](MEDIA_MAINTENANCE.md)。
